# Release 规范（待确认）

## 版本

- 正式版：`x.y.z`
- 测试版：`x.y.z-beta.N`
- 正式版与测试版轮流推进
- 测试版可以领先正式版多个版本
- 已发布版本保留，不删除

## Tag

- 正式版 tag 与版本号一致：`0.3.5`
- 测试版 tag：`0.3.7-beta.2`
- Release 标题只写版本：`0.3.5`、`0.3.7 Beta 2`

## 安装包

- Android：`<产品名>-<版本号>.apk`
- 示例：
  - `TokiNote-0.3.5.apk`
  - `TokiTodo-0.1.0-beta.1.apk`
  - `Luma-0.1.0-beta1-android.apk`

多平台项目保留平台后缀；单平台项目不再加后缀。

## Release Notes

```markdown
# 新增功能

## I. 功能名称

一句话说明用户现在能做什么。

## II. 功能名称

一句话说明用户现在能做什么。

# 设计特性

## I. 设计特性名称

一句话说明界面、动效或交互的变化。
```

规则：

- 只写用户能感知的内容
- 不写内部实现、提交记录、构建过程
- 功能用「新增功能」，视觉与交互用「设计特性」
- 没有对应内容时写「无」，不硬凑条目
